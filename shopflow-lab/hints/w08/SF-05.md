# SF-05 order timestamps: hint ladder

Open ONE level at a time, and only after you have tried for 10 minutes.

<details><summary>Level 1: symptom only</summary>

Most `OrderServiceTest` tests are red because `place`, `displayFor` and the promise methods return placeholder values. Start with `placing an order`: it needs only one line of production code.
</details>

<details><summary>Level 2: where to look</summary>

The class already receives a `Clock` in its constructor and keeps it in a field. Ask the clock for the time instead of constructing `Instant.EPOCH`. For display and promises, think about which type represents "an instant seen on a wall clock".
</details>

<details><summary>Level 3: the tool</summary>

Write a tiny `main` or a jshell session: `Instant.parse("2025-03-09T07:00:00Z").atZone(ZoneId.of("America/New_York"))`. Print it. Then try `DateTimeFormatter.ofPattern("uuuu-MM-dd HH:mm:ss xxx")` on that value (`xxx` prints the offset such as `-04:00`).
</details>

<details><summary>Level 4: the concept to search</summary>

Search: "Instant plus Duration vs ZonedDateTime plusDays DST" and "Jackson JavaTimeModule WRITE_DATES_AS_TIMESTAMPS".
</details>

<details><summary>Level 5: fix outline</summary>

- `place`: `new Order(id, clock.instant())`.
- `displayFor`: a static `DateTimeFormatter` with pattern `uuuu-MM-dd HH:mm:ss xxx` applied to `placedAt().atZone(zone)`.
- `promisedBy`: `placedAt().plus(Duration.ofHours(24))`.
- `nextDaySameLocalTime`: `placedAt().atZone(zone).plusDays(1).toInstant()`.
- `isLate`: `deliveredAt.isAfter(promisedBy(order))`.
- JSON: an `ObjectMapper` with `JavaTimeModule` registered and `SerializationFeature.WRITE_DATES_AS_TIMESTAMPS` disabled; wrap `JsonProcessingException`.
</details>
