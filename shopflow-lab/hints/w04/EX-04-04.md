# EX-04-04: Basket defensive copy (hardest exercise of the week)

Open **one level at a time**, and only after you have tried for about 10 minutes at the previous level.
Write down what you tried before opening the next level.

<details><summary>Level 1: the symptom, restated</summary>

Changing the list you passed to the constructor changes the basket, or the list returned by `skus()` can be modified by the caller.

</details>

<details><summary>Level 2: where to look</summary>

Two separate leaks: one at the *entrance* (constructor stores the caller's list) and one at the *exit* (getter returns the internal list).

</details>

<details><summary>Level 3: which tool to use</summary>

Draw two boxes labelled 'caller list' and 'basket.skus'. After the constructor, how many arrows point to the same list object? Print `System.identityHashCode` of both to confirm.

</details>

<details><summary>Level 4: the concept to search for</summary>

Search for: *defensive copy Java*, *List.copyOf*, *unmodifiable view vs immutable copy*. Read Effective Java Item 50 (make defensive copies when needed).

</details>

<details><summary>Level 5: the shape of the fix (try to write it yourself first)</summary>

Copy on the way in with `List.copyOf(skus)`; that copy is also immutable, so the getter can return it directly. `List.copyOf(null)` throws `NullPointerException`, which is what the null test expects.

</details>
