# INC-04-01: cart items duplicate and vanish (RL-04)

Open **one level at a time**, and only after you have tried for about 10 minutes at the previous level.
Write down what you tried before opening the next level.

<details><summary>Level 1: the symptom, restated</summary>

Adding the same product twice puts two entries in the cart, `contains` returns false for a product that is in the cart, and `remove` does nothing. But `ProductListing.equals` is correct when you call it directly (the guard test proves it).

</details>

<details><summary>Level 2: where to look</summary>

The cart stores listings in a `HashSet`. Think about what a hash-based collection does *before* it ever calls `equals`. What does `ProductListing` inherit if you don't override the thing it uses first?

</details>

<details><summary>Level 3: which tool to use</summary>

In a scratch `main` or a debugger watch, print `a.hashCode()` and `b.hashCode()` for two listings with the same SKU. Step into `HashSet.add` with the debugger and look at which bucket each object lands in. In IntelliJ, *Generate -> equals() and hashCode()* shows the pair.

</details>

<details><summary>Level 4: the concept to search for</summary>

Search for: *Java equals hashCode contract*, *HashMap how it works buckets*, *Object.hashCode default identity*. Read Effective Java Item 11 (always override hashCode when you override equals) and Item 10.

</details>

<details><summary>Level 5: the shape of the fix (try to write it yourself first)</summary>

Add a `hashCode` that is consistent with `equals`: it must use exactly the fields that `equals` uses (here only the SKU). Then do the follow-up in `MoneyInSetTest`: your own `Money` needs the same treatment, and `BigDecimal` fields are already well behaved in `Objects.hash`.

</details>
