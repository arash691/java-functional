# INC-39/40 hints: wrong day, lost cents

<details><summary>Level 1</summary>

Two different problems in one ticket: a date that is "the wrong day" for some users, and money that loses digits. Treat them separately.
</details>

<details><summary>Level 2</summary>

Call the endpoint and look at the raw JSON. Does the date say which time zone it is in? Is the money a JSON number or a string?
</details>

<details><summary>Level 3</summary>

Paste the JSON into Node: `node -e 'console.log(JSON.parse(process.argv[1]))' '<json>'`. Compare `new Date("2026-11-02T23:30:00")` with `new Date("2026-11-02T23:30:00Z")` under `TZ=Asia/Tokyo`.
</details>

<details><summary>Level 4</summary>

Search: "java LocalDateTime vs Instant REST API", "JavaScript Number MAX_SAFE_INTEGER money", and the Jackson annotation `@JsonFormat(shape = STRING)`.
</details>

<details><summary>Level 5</summary>

`Instant` serializes as an ISO-8601 string that ends with `Z`. For money, keep `BigDecimal` in Java but serialize it as a JSON string with `@JsonFormat(shape = JsonFormat.Shape.STRING)` on the record component. Remember to produce the `Instant` from the injected `Clock` (`Instant.now(clock)`).
</details>
