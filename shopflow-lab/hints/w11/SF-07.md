# SF-07 hints: spec first, then the whole Catalog API

<details><summary>Level 1</summary>

Do not touch the controller yet. Finish `catalog.openapi.yaml` first and run `Sf07SpecContractTest`. Its failure messages tell you what is missing.
</details>

<details><summary>Level 2</summary>

Copy the style of the finished `GET /api/products/{id}` operation. The path-level `parameters` block can be shared by `get`, `put` and `delete` of `/api/products/{id}`.
</details>

<details><summary>Level 3</summary>

Every error response must declare `application/problem+json`. List operation: query parameters `page` and `size`. Schemas needed: `ProductRequest`, `ProductResponse`, the page schema and `Problem`.
</details>

<details><summary>Level 4</summary>

Paste your YAML into the Swagger Editor (editor.swagger.io): it shows syntax errors and renders the documentation.
</details>

<details><summary>Level 5</summary>

For the code: `PUT` and `DELETE` just call `service.update` / `service.delete`; the exceptions `ProductNotFoundException` (404) and `DuplicateSkuException` (409) are turned into `ProblemDetail`s in `ApiExceptionHandler` with `@ExceptionHandler`.
</details>
