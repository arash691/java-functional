# SF-04: InventoryStore (JSON)

Open one level at a time, and only after you have tried for about 10 minutes at the current level.

<details><summary>Level 1: the symptom, restated</summary>

All `InventoryStoreTest` tests fail with `UnsupportedOperationException: TODO SF-04`.

</details>

<details><summary>Level 2: where to look</summary>

Start with the round-trip test (`Saving.roundTrip`): `save` then `load`. Make that one green, then do one error case at a time.

</details>

<details><summary>Level 3: which tool to use</summary>

Use a small private `record StoreFile(Integer version, Map<String,Integer> stock)` and a single shared `ObjectMapper`. Print the JSON of a save to see what Jackson produces. Sort the keys by copying into a `TreeMap` before writing.

</details>

<details><summary>Level 4: the concept to search for</summary>

Search: "Jackson records deserialization", "Jackson JsonProcessingException hierarchy", and Effective Java Item 73 (exception translation). Which Jackson exception does an empty file raise?

</details>

<details><summary>Level 5: the shape of the fix</summary>

Separate the three steps in `load`: (1) read the file, translating `NoSuchFileException` to "not found" and other `IOException`s to a generic message; (2) parse, translating `JsonProcessingException` to "corrupt"; (3) validate version and quantities. Always keep the original exception as the cause and put the file path in the message.

</details>
