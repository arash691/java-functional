# INC-07-2: file handles pile up on report failures

Open one level at a time, and only after you have tried for about 10 minutes at the current level.

<details><summary>Level 1: the symptom, restated</summary>

When reading fails half-way the stream is never closed (the test checks `isClosed()`).

</details>

<details><summary>Level 2: where to look</summary>

Follow the path of the `BufferedReader` in `countLines`: where is `reader.close()` called, and what happens if `readLine` throws before that line?

</details>

<details><summary>Level 3: which tool to use</summary>

Run `LineCounterTest.closedWhenReadingFails`. The tracking stream records `close()`. Add a breakpoint in the `catch` block: has `close` run yet?

</details>

<details><summary>Level 4: the concept to search for</summary>

Search: "try-with-resources" and Effective Java Item 9 (prefer try-with-resources to try-finally). Also: what does closing a `BufferedReader` close?

</details>

<details><summary>Level 5: the shape of the fix</summary>

Declare the reader in the `try ( ... )` header. Closing the outer reader closes the wrapped streams, and a failure while closing is added as a suppressed exception instead of hiding the original one.

</details>
