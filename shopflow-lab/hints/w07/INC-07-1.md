# INC-07-1: the import says success but nothing was saved

Open one level at a time, and only after you have tried for about 10 minutes at the current level.

<details><summary>Level 1: the symptom, restated</summary>

Operations report `success=true` and a count, but the target file does not exist (or the input file was never read).

</details>

<details><summary>Level 2: where to look</summary>

Read the end of `ImportService.importCsv`: what happens to an `IOException` thrown by `Files.write` or `Files.readAllLines`?

</details>

<details><summary>Level 3: which tool to use</summary>

Temporarily log the exception inside the `catch` block (`e.printStackTrace()`) and rerun the failing test: which exception is it, and where does it come from? Then remove the print.

</details>

<details><summary>Level 4: the concept to search for</summary>

Search: "Java swallowing exceptions empty catch block" and Effective Java Items 70 (checked vs runtime), 73 (translate exceptions) and 77 (don't ignore exceptions).

</details>

<details><summary>Level 5: the shape of the fix</summary>

Catch only what you can handle. The `NumberFormatException` for a bad line is expected and counted; an `IOException` is not. Catch `IOException`, wrap it in `ImportException` with a message naming both files, and pass the original as the cause.

</details>
